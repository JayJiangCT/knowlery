# Knowlery 1.5.0 — agent parity acceptance (local agent test note)

Branch: `cursor/agents-md-parity-614b` (PR #74). This note is written for an
agent with a shell running inside the maintainer's real vault ("Jay WorkSpace").
Execute every case, record PASS / FAIL / BLOCKED with evidence (command output
or a screenshot reference), and finish with the summary table at the end.

Read-only discipline: nothing in this plan modifies user notes. The only files
touched are Knowlery's own config files (`AGENTS.md`, `.claude/CLAUDE.md`,
`.agents/rules/`, `.knowlery/`) and, in one clearly marked step, a temporary
rule file you create and delete yourself.

> **Revision (reference, not inline).** After the first local run the layout
> changed: `KNOWLEDGE.md` and the rules are no longer copied into `AGENTS.md`.
> `AGENTS.md` (Codex/OpenCode) opens with a **Read First** section that names
> `KNOWLEDGE.md` and each rule path, then carries the operating rules;
> `.claude/CLAUDE.md` (Claude Code) `@`-imports `KNOWLEDGE.md` and each rule
> and inlines the operating rules, and no longer imports `AGENTS.md`. Claims
> 1, 2, 4 and the affected cases (T1, T2, T5, T6, T7, T13) are rewritten below;
> results recorded against the earlier wording should be re-run.

## What changed (the claims under test)

1. `AGENTS.md` at the vault root is the entry file for Codex / OpenCode /
   Cursor. Its `<!-- Knowlery managed:start -->` … `<!-- Knowlery managed:end -->`
   block holds a **Read First** section (read `KNOWLEDGE.md` first; then each
   listed `.agents/rules/<file>.md`) followed by Knowlery's operating rules
   rendered from the template. Nothing from `KNOWLEDGE.md` or the rule files
   is copied into it. `KNOWLEDGE.md` itself is only your description of the
   knowledge base.
2. `.claude/CLAUDE.md` is the entry file for Claude Code: a managed block with
   `@../KNOWLEDGE.md`, the operating rules inlined, and one
   `@../.agents/rules/<file>.md` import per rule. No `@../AGENTS.md`.
   Claude-specific text outside the block is preserved across syncs.
3. `.agents/rules/` is the only rules directory. Upgrade **copies**
   `.claude/rules/**/*.md` into it (never deletes). Both blocks are
   regenerated on plugin load, rule add/remove, and `knowlery sync`; text
   outside the markers is kept. "Reset AGENTS.md" in settings is the only
   path that drops it.
4. Rule bodies are not inlined anywhere, so Claude `paths:` frontmatter
   reaches Claude as-is through the import and never appears in `AGENTS.md`.
5. The Knowlery-written vault-level `opencode.json` is retired.
6. `/ask` (and the operating card) tell agents to query with 2–6 subject
   terms, retry once with keywords on abstention, and never use `INDEX.base`
   as a retrieval step.
7. The platform switch in settings no longer generates or deletes files.

## Preconditions

- Dev build of the branch installed in the vault's plugin folder; Obsidian
  reloaded at least once since install (this runs the version sync).
- `knowlery` CLI on PATH, built from the same branch (needed for T9, T12,
  T13). If the CLI is older than the branch, mark those cases BLOCKED rather
  than failing them.
- Claude Code, Codex CLI, and OpenCode installed and able to open the vault
  directory. Record each tool's version in the report.
- Do **not** run T4 (Reset) until T1–T3 and T6 have been recorded: T6 wants
  the pre-reset state.

## Test cases

### T1 — Upgrade migration produced the new layout

```bash
ls .agents/rules/
ls .claude/rules/
cat .claude/CLAUDE.md
grep -c '<!-- Knowlery managed:start -->' AGENTS.md
grep -c '<!-- Knowlery managed:end -->' AGENTS.md
grep -c '^## Read First' AGENTS.md
grep -c '^# ' AGENTS.md
ls opencode.json 2>/dev/null || echo "no opencode.json"
```

Expected:

- Every file in `.claude/rules/` also exists in `.agents/rules/` with
  identical content for files that did not previously exist there
  (`diff .claude/rules/<f> .agents/rules/<f>` is empty). `.claude/rules/` is
  unchanged (copy, not move).
- `.claude/CLAUDE.md` starts with `<!-- Knowlery managed:start -->`; inside
  the block: `@../KNOWLEDGE.md` before `## Operating Rules`, then exactly one
  `@../.agents/rules/<file>` line per file in `.agents/rules/`. No
  `@../AGENTS.md`, `@rules/`, `@../SCHEMA.md`, `@../INDEX.base` lines
  anywhere. Any Claude-specific text the maintainer had is still there, after
  the block.
- Both marker counts are 1 in each file; `## Read First` count is 1.
- `# ` heading count in `AGENTS.md` equals the headings in the hand-written
  part, if any (0 after T4): the block contributes only `## ` sections, and
  the KB title and rule headings are no longer inlined.
- No `opencode.json`, or one that contains no `KNOWLEDGE.md` /
  `.agents/rules/*.md` entries in `instructions`.
