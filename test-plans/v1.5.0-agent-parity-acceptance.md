# Knowlery 1.5.0 — agent parity acceptance (local agent test note)

Branch: `cursor/agents-md-parity-614b` (PR #74). This note is written for an
agent with a shell running inside the maintainer's real vault ("Jay WorkSpace").
Execute every case, record PASS / FAIL / BLOCKED with evidence (command output
or a screenshot reference), and finish with the summary table at the end.

Read-only discipline: nothing in this plan modifies user notes. The only files
touched are Knowlery's own config files (`AGENTS.md`, `.claude/CLAUDE.md`,
`.agents/rules/`, `.knowlery/`) and, in one clearly marked step, a temporary
rule file you create and delete yourself.

## What changed (the claims under test)

1. `AGENTS.md` at the vault root is the single fixed context for every agent:
   `KNOWLEDGE.md` + every rule in `.agents/rules/` inlined inside a
   `<!-- Knowlery managed:start -->` … `<!-- Knowlery managed:end -->` block.
   Codex / OpenCode / Cursor read it directly.
2. `.claude/CLAUDE.md` is a one-line `@../AGENTS.md` import. Claude-specific
   text below the import is preserved across syncs.
3. `.agents/rules/` is the only rules directory. Upgrade **copies**
   `.claude/rules/**/*.md` into it (never deletes). The block is regenerated
   on plugin load, rule add/remove, and `knowlery sync`; text outside the
   markers is kept. "Reset AGENTS.md" in settings is the only path that drops
   it.
4. Rules with Claude `paths:` frontmatter are inlined with the scope restated
   as `_Applies to files matching: …_` (no raw `---` / `paths:` in the block).
5. The Knowlery-written vault-level `opencode.json` is retired.
6. `/ask` (and the operating card) tell agents to query with 2–6 subject
   terms, retry once with keywords on abstention, and never use `INDEX.base`
   as a retrieval step.
7. The platform switch in settings no longer generates or deletes files.

## Preconditions

- Dev build of the branch installed in the vault's plugin folder; Obsidian
  reloaded at least once since install (this runs the version sync).
- `knowlery` CLI on PATH, built from the same branch (needed for T9, T12,
  T13). If the CLI is older than the branch, mark those cases BLOCKED rather
  than failing them.
- Claude Code, Codex CLI, and OpenCode installed and able to open the vault
  directory. Record each tool's version in the report.
- Do **not** run T4 (Reset) until T1–T3 and T6 have been recorded: T6 wants
  the pre-reset state.

## Test cases

### T1 — Upgrade migration produced the new layout

```bash
ls .agents/rules/
ls .claude/rules/
cat .claude/CLAUDE.md
grep -c '<!-- Knowlery managed:start -->' AGENTS.md
grep -c '<!-- Knowlery managed:end -->' AGENTS.md
grep -c '^# ' AGENTS.md
ls opencode.json 2>/dev/null || echo "no opencode.json"
```

Expected:

- Every file in `.claude/rules/` also exists in `.agents/rules/` with
  identical content for files that did not previously exist there
  (`diff .claude/rules/<f> .agents/rules/<f>` is empty). `.claude/rules/` is
  unchanged (copy, not move).
- `.claude/CLAUDE.md` first line is exactly `@../AGENTS.md`. No `@rules/`,
  `@../KNOWLEDGE.md`, `@../SCHEMA.md`, `@../INDEX.base` lines. Any
  Claude-specific text the maintainer had below the imports is still there.
- Both marker counts are 1.
- `# ` heading count equals: (headings in the hand-written part, if any) +
  1 (`KNOWLEDGE.md` title) + number of files in `.agents/rules/`.
- No `opencode.json`, or one that contains no `KNOWLEDGE.md` /
  `.agents/rules/*.md` entries in `instructions`.

### T2 — Path-scoped rules are restated, not leaked

```bash
awk '/Knowlery managed:start/,/Knowlery managed:end/' AGENTS.md > /tmp/knowlery-block.md
grep -n '^---$' /tmp/knowlery-block.md
grep -n '^paths:' /tmp/knowlery-block.md
grep -n '_Applies to files matching:' /tmp/knowlery-block.md
```

Expected: the first two greps print nothing; the third prints one line per
rule that has `paths:` frontmatter (in this vault: `agent-pages.md` and
`user-notes-readonly.md`), each directly under that rule's `# ` heading.

### T3 — No mtime churn on reload

```bash
stat -f '%m %N' AGENTS.md .claude/CLAUDE.md   # macOS; use stat -c '%Y %n' on Linux
```

Reload Obsidian (or disable/enable the plugin) twice, then run the same
command. Expected: identical timestamps.

### T4 — Reset AGENTS.md (explicit, destructive, user-initiated)

Before running: copy the hand-written section above the start marker to
`/tmp/agents-md-user-part.md` so the maintainer can restore what they want.

Settings → Knowlery → "Regenerate agent config" → **Reset AGENTS.md** →
Confirm.

```bash
head -1 AGENTS.md
grep -c 'AI Agent Guide' AGENTS.md
grep -c '^# ' AGENTS.md
```

Expected: first line is `<!-- Knowlery managed:start -->`; the second grep
prints 0; heading count is 1 + number of rule files. `KNOWLEDGE.md` and
`.agents/rules/` are byte-identical to before (compare with `git status` if
the vault is a repo, otherwise with checksums taken in T1).

Then append, **below** the end marker, the three sections the maintainer
wants to keep (Source priority, Active Projects, Sprint Cycle), reload
Obsidian, and confirm they survived and the block was not duplicated
(`grep -c 'managed:start' AGENTS.md` is still 1).

### T5 — Rule and KNOWLEDGE.md edits propagate

1. Settings → Rules → add a rule `zz-acceptance-probe.md` with body
   `# Acceptance Probe\n\nPROBE-7f3a`. Expected: `grep -c PROBE-7f3a
   AGENTS.md` prints 1 immediately (no reload needed).
2. Delete that rule from the Rules UI. Expected: the grep prints 0.
3. Close Obsidian. Append a line `PROBE-KM-9c1d` to the end of `KNOWLEDGE.md`
   with a text editor. Open Obsidian. Expected: `grep -c PROBE-KM-9c1d
   AGENTS.md` prints 1. Remove the probe line from `KNOWLEDGE.md` and reload;
   expected: 0.

### T6 — Claude Code loads the chain (before T4)

Open Claude Code in the vault root and run `/context all`. Under "Memory
files" expect:

- `.claude/CLAUDE.md` (small, ~15 tokens if the maintainer kept nothing
  below the import).
- `AGENTS.md` listed as its own entry — this proves the `@../AGENTS.md`
  import resolved.
- The `.claude/rules/*.md` files **without** `paths:` frontmatter (the copy
  policy leaves them in place; Claude auto-loads them). The `paths:` ones
  should be absent at launch.

Then ask: "Which directories in this vault does the agent own, and which are
read-only?" Expected: the answer names `entities/`, `concepts/`,
`comparisons/`, `queries/` as agent-owned and everything else as user notes,
without reading any file first (it is already in context).

Optional follow-up for the maintainer: delete `.claude/rules/` and re-run
`/context all`; Memory files should drop to `~/.claude/CLAUDE.md`,
`.claude/CLAUDE.md`, `AGENTS.md`, and the memory token total should fall.

### T7 — Codex loads AGENTS.md and queries correctly (after T4)

Open Codex in the vault root.

```bash
codex debug agents-md   # if available in this Codex version
```

Expected: the vault `AGENTS.md` appears in the loaded chain.

Ask the ownership question from T6. Expected: same answer, no file reads.

Then ask, in Chinese: 「Rob 最近提出的 Dimensions & Weight Eligibility Check
方案是什么？」 and watch the tool calls. Expected:

- Codex does **not** run `obsidian read file="INDEX.base"` first.
- Codex does **not** re-read `KNOWLEDGE.md` or individual rule files (they
  are inlined; the old top section that demanded this is gone after T4).
- Codex does **not** try `obsidian read` on a skill file, and never on a
  home-directory path such as `~/.agents/skills/ask/SKILL.md` (earlier run
  did exactly this and got `Error: … not found` with exit 0). If it reads a
  skill at all, it uses its file tools on the vault-relative
  `.agents/skills/<name>/SKILL.md`. Requires the refreshed operating card
  (T10) — before T10 this bullet is expected to fail on this vault.
- The `knowlery:query` / `knowlery query` call carries subject terms only
  (something like `Rob Dimensions Weight Eligibility Check`), not the full
  sentence and not request phrasing such as 请返回 / 相关 / 最新记录.
- The result cites `queries/zipline-pack-as-eligibility-oracle-direction-2026-08-20.md`
  and/or `queries/1p-drone-delivery-weight-and-dimension-eligibility-current-proposal-2026-08-31.md`.

If the first query still abstains, expect exactly one retry with keywords
before any "the vault does not cover this" statement.

### T9 — Query phrasing regression (CLI, deterministic)

```bash
knowlery query "Rob Dimensions Weight Eligibility Check" | head -3
knowlery query "Rob 最近提出的 Dimensions & Weight Eligibility Check 方案是什么？请返回相关的最新原始记录、决策上下文、讨论和待验证假设。" | head -1
```

Expected: the first returns ranked candidates led by the two pages named in
T7; the second prints `No confident matches in this vault for: …`. The
second is a **known engine limitation** (request words weighted by CJK
length dominate coverage); it is why the skill now teaches subject-term
queries. An engine-side fix is tracked separately — do not fail this case on
the abstention, fail it only if the first command abstains.

### T10 — Operating card is current (manual, maintainer)

Knowlery-authored sections are stale: Knowledge Retrieval still describes the

dot-directory boundary, and Available Skills lacks the skills path. Generate

an empty temp directory and replace those three sections (`## Operating

grep -c 'Obsidian CLI reaches only notes in the vault index' AGENTS.md # 1

Run T7 (Codex) again after this step.
