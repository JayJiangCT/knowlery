# Knowlery 1.5.0 — "reference, not inline" acceptance (local agent test note)

Branch: `cursor/reference-knowledge-md-423c` (PR #75, on top of PR #74). Written
for an agent with a shell running inside the maintainer's real vault. Execute
every case, record PASS / FAIL / BLOCKED with evidence (command output or a
screenshot reference), and finish with the summary table at the end.

Read-only discipline: nothing in this plan modifies user notes. The only files
touched are Knowlery's own (`AGENTS.md`, `.claude/CLAUDE.md`, `.agents/rules/`,
`.knowlery/`) and, in two clearly marked steps, a temporary rule file and a
probe line in `KNOWLEDGE.md` that you remove yourself.

> **Revision 3 (after two failed runs of the soft reference).** `AGENTS.md`
> no longer asks Codex/OpenCode to read `KNOWLEDGE.md` and the rules; it
> copies them in again (OpenCode went straight to a skill both times and
> never read either). Claude's path is unchanged. Claims 1–2 and cases R1,
> R5, R6, R9, R10, R12 are rewritten below.

## What changed (the claims under test)

1. `KNOWLEDGE.md` is the standalone source. `.claude/CLAUDE.md` `@`-imports
   it first; `AGENTS.md` carries a copy of it, regenerated on sync.
2. `AGENTS.md` (Codex / OpenCode / Cursor entry) = managed block with
   `KNOWLEDGE.md` copied in, then Knowlery's operating rules, then every rule
   body from `.agents/rules/` (Claude `paths:` frontmatter restated as
   `_Applies to files matching: …_`). No `## Read First`, no `@` imports.
3. `.claude/CLAUDE.md` (Claude Code entry) = managed block with
   `@../KNOWLEDGE.md`, the operating rules inlined, one
   `@../.agents/rules/<file>.md` per rule. No `@../AGENTS.md`.
4. Rule add/delete re-renders both entry files. A `KNOWLEDGE.md` edit
   re-renders `AGENTS.md` (the copy) and leaves `.claude/CLAUDE.md` alone.
5. The pre-1.5 `## Operating Rules` / `## Knowledge Retrieval` /
   `## Available Skills` sections are removed from `KNOWLEDGE.md` on sync and
   on every plugin load; user-added `###` subsections under them survive as
   `##`; the original is backed up once to
   `.knowlery/backups/KNOWLEDGE.pre-1.5.md`.
6. Both entry files are write-on-change (no mtime churn on reload).

## Preconditions

- Plugin built from the branch and installed; Obsidian reloaded at least once
  since install.
- `knowlery` CLI on PATH, built from the same branch (needed for R7, R12). If
  it is older than the branch, mark those cases BLOCKED rather than failing.
- Claude Code, Codex CLI, and OpenCode installed and able to open the vault.
  Record each tool's version.
- Run R1–R7 before any of R8–R11 (the agent sessions), and R11 (Reset) last.

## Test cases

### R1 — AGENTS.md structure

```bash
grep -c '<!-- Knowlery managed:start -->' AGENTS.md
grep -c '<!-- Knowlery managed:end -->' AGENTS.md
grep -c '^## Read First' AGENTS.md
grep -c '^## Operating Rules' AGENTS.md
grep -c '^## Knowledge Retrieval' AGENTS.md
grep -c '^## Available Skills' AGENTS.md
grep -c '^@' AGENTS.md
grep -n 'INDEX.base' AGENTS.md
wc -c AGENTS.md
```

Expected: markers 1 each; `## Read First` 0; the three operating-rule H2s 1
each; `^@` 0; the only `INDEX.base` line says it is "a human preview of
compiled pages, not a retrieval step"; size well under 32768 bytes (Codex
`project_doc_max_bytes`; ~10 KB with a cleaned-up `KNOWLEDGE.md`).

```bash
awk '/Knowlery managed:start/,/Knowlery managed:end/' AGENTS.md > /tmp/agents-block.md
grep -v '^$' KNOWLEDGE.md | while IFS= read -r l; do grep -qF -- "$l" /tmp/agents-block.md || echo "MISSING: $l"; done
sed -n '4p' /tmp/agents-block.md
grep -c '^# ' /tmp/agents-block.md
find .agents/rules -name '*.md' | wc -l
grep -c '^---$' /tmp/agents-block.md
grep -c '^paths:' /tmp/agents-block.md
grep -c '_Applies to files matching:' /tmp/agents-block.md
```

Expected: the loop prints nothing (every line of `KNOWLEDGE.md` is in the block)
and line 4 of the block is the KB title (`KNOWLEDGE.md` opens the block);
`# ` count = 1 (KB title) + rule-file count (each rule's own `# ` heading);
`---` and `paths:` 0; one `_Applies to files matching:` line per rule that has
`paths:` frontmatter (in this vault: `agent-pages.md`, `user-notes-readonly.md`).
