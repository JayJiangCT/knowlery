# T09 — Recover the cited text via git

**Fixture applied by `tools/build.py`:** Same fixture as T04 (the Medium Bag note was changed after the pages cited it).

## Prompt (verbatim, identical for both arms)

```
Start by reading the instruction file at the vault root (`AGENTS.md`; and `CONVENTIONS.md` if it exists) and follow it. Obsidian is not running: use file tools (read, search, edit). Do not use the network. Do not run git commit or push. Work only inside this vault.

The `drone-delivery-integration-strategy` page cites the Medium Bag Slack note. That note has since been edited. Show the exact text of the note **as the page cited it** (before the edit), and explain how you established that it is that version and not another. The vault's git history is available read-only.

When you are done, write your answer to a new file `ANSWER.md` at the vault root: the answer itself, the vault-relative paths you relied on, and anything you were unable to establish. If the task asked you to change the vault, `ANSWER.md` also lists every file you changed and why.
```

## Pass criteria

Test: uses the `blob:` on the `## Sources` line (`git cat-file -p <blob>`), strips the frontmatter, and shows the pre-edit body; explains that the sha256 digest alone cannot be fetched from git and that the blob is the recoverable object. Control: can only use `git log`/`git show` on the path with a date argument and must say the choice of version is inferred. Fail: claims to have fetched text by the sha256 digest, or shows the current text as the cited version.

## Record per run

Correct version shown y/n; correct mechanism explained y/n; false recovery claim (fail); tokens.
