# GR-002 — 未链接知识的潜在关联只作为临时检索候选

**日期：** 2026-11-03  
**状态：** ACCEPTED（Owner 明确同意 Agent 可发现没有显式链接的潜在知识关联，但不得在检索阶段自动写回）  
**范围：** Knowlery 2.0 / Graph-guided Retrieval  
**相关决定：** GR-001、A-002、A-004、F-006、F-008、CLI-001

## 已接受的决定

1. 当 Raw Notes、Knowledge Pages 或其他 Vault 内容之间不存在显式 Wikilink / Backlink / KF 关系时，Agent **可以基于内容及语义判断发现潜在相关性**，将其用于知识检索与探索；缺少现有链接不能成为排除 Raw Note 的充分理由。
2. **潜在关联在检索阶段是临时候选（ephemeral retrieval candidate），不是已验证的知识关系或证据**。检索不得仅凭这种推断就自动修改 Raw Notes、Knowledge Pages、Wikilinks、KF 关系或其他持久 Vault 资产。
3. Agent 可进一步打开并验证候选内容。在适用的知识编译或演进工作流中，经过证据与 KF 约束检查后，才可以按独立的、受控的知识更新流程持久化真实关系；**检索本身不隐式触发写入**。此决定不新设所有写入都需 Owner 逐次批准的规则，也不绕过已有治理。
4. 临时候选不能被表达为已确认的 `Sources` 证据、`derived` 依赖或正式演进关系。知识答案仍遵循 KF v1.0 的来源核查（F-008）。

## 设计背景

Owner 的 1.x 使用经验表明：Raw Notes 主要由人创建，通常缺乏显式链接；Agent 编译生成的 LLM Wiki 则更可能建立页面关联。Knowlery 应能探索未建立链接的原始资料，同时避免把 Agent 对语义相关性的猜测直接当作知识事实。GR-001 已把 KF 语义关系与普通导航关系区分；GR-002 进一步明确**尚未建立的关系可被发现，但不能被当作现有关系**。

## 尚待设计和验证（OPEN / PROPOSED）

- 潜在关联使用什么发现机制（词法、别名、语义模型、批量候选等）以及成本控制。
- 临时候选的输出契约、置信度解释、去重与是否允许非权威派生缓存。
- 何时主动展开关系、停止条件、Token 预算和 Evidence Pack 组装方式。
- 在 Obsidian / Headless 之间如何实现一致的语义与复现实验。

**范围边界：** 本决定仅确认检索与写入的行为边界；不构成 CLI-002 具体命令、算法、运行模式或实施授权。
