# GR-008 — 分层 Evidence Pack 与按需证据展开

**日期：** 2026-11-03  
**状态：** ACCEPTED（Owner 明确认可「默认精简知识入口和关联索引，按需展开正文」）  
**范围：** Knowlery 2.0 / Graph-guided Retrieval 的输出与渐进式证据读取原则  
**相关决定：** GR-001、GR-002、GR-003、GR-004、GR-005、GR-006、GR-007、CLI-001、F-006、F-008

## 已接受的决定

1. **分层 Evidence Pack（证据包）是默认检索输出原则。** 第一轮优先返回精简的知识入口（候选目标、标题/描述、相关 Claim 定位、可确定的命中线索）及关联/证据索引，而不是无条件输出 Top-K 页面或所有相邻笔记的 Markdown 全文。
2. **发现与展开分离。** 关联索引可以标记 KF Source、Record、`derived`、History、Wikilink、Backlink 等关系及其目标定位；Agent 依据用户问题和证据缺口再请求指定 Claim、Record 或 Source 的详细内容。
3. **保持关系的证据语义边界。** 普通导航关系或 GR-002 的隐含关联候选不能仅因出现在 Evidence Pack 中就被称为已验证证据；`derived` 不是独立来源。关系类型、内容是否已读取、验证状态、未检查/失效/截断情况应能明确区分。
4. **保留可追溯和继续读取的路径。** Evidence Pack 应提供后续读取所需的定位与版本前置条件，适用 GR-006 完整证据单元和 GR-007 无状态续读原则；任何片段展示不得冒充完整 Source 或已完成 F-008 来源校验。
5. **遵守 KF v1.0 渐进披露与来源核查。** 默认精简是为了降低无关上下文消耗，不得因此绕过 F-008 对回答中使用的 Claim 的来源检查或忽略已知的争议、失效证据。

## 分层的设计方向（不预设实现字段）

- **第一层：知识入口。** 描述、相关 Claim 定位、命中原因等少量候选信息。部分“命中原因”属于检索算法解释而非事实证明。
- **第二层：关联与证据索引。** 关系类型、目标身份、导航/语义类别及实际可观测的核查状态；仅发现不强制加载全部正文。
- **第三层：按需证据内容。** 指定 Claim、Record 的相关范围或 Source 片段，加上来源定位、版本/校验与部分性状态。需要完整 Source 验证时仍遵守 KF F-008。

这三层是**逻辑上的渐进读取形态**，不要求 CLI 在每次操作中把三个层级完整返回，也不定义必须使用几个具体命令。

## 可实现性与边界

- 已有 Markdown/KF 文档结构、路径、Claim anchors、Sources、History 以及 Obsidian CLI 的链接/文件访问能力，为按需构建这些层次提供实现基础；**当前不宣称 CLI-002 已实现或通过测试**。
- 知识入口中可以机械地读取标题、描述、字段、锚点；“哪些 Claim 最能回答用户的问题”仍可能要求 Agent 的语义判断，不将其错误写成 CLI 可靠的确定性保证。
- 索引不是知识真值。外部编辑、缺失链接、文件迁移、部分失效或缓存过期可能导致索引与实际内容不同；用版本前置条件和按需核验防止混淆，但不承诺跨整个 Vault 的快照一致性。
- 重要失败路径：索引未发现相关 Source、导航链接误关联、候选描述误导、预算不足以返回完整证据。必须有可识别的缺失/未验证/截断语义。

## 仍待决定（OPEN / PROPOSED）

- Evidence Pack JSON 字段、具体检索 CLI 命令、默认大小、不同层的触发方式。
- 初始候选选择、索引排序、语义意图判断的 Agent/CLI 责任细分。
- Obsidian/Headless Adapter 对齐程度与缓存新鲜度。
- 与直接返回全文、普通 Top-K 检索相比，在固定任务预算下的证据覆盖率、正确率、拒答率和 Token 消耗评测。

**范围：** 本决策批准分层返回与按需展开的原则，并未批准 CLI-002 整体架构、Evidence Pack Schema 或实现。
