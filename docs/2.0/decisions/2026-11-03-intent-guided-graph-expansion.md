# GR-003 — 意图驱动的选择性关系扩展

**日期：** 2026-11-03  
**状态：** ACCEPTED（Owner 对「默认发现关系，但依据当前问题选择性读取内容，而非固定一跳或两跳展开」明确表示认可）  
**范围：** Knowlery 2.0 / Graph-guided Retrieval 行为原则（非 CLI-002 命令接口或实现批准）  
**相关决定：** GR-001、GR-002、A-004、F-006、F-008、CLI-001

## 已接受的决定

1. **检索时区分发现（Discover）和展开（Expand）。** 发现阶段可返回关联目标的身份、关系类型及少量定位元数据，不必默认将关联笔记正文纳入 Agent 上下文；展开阶段才按需读取具体内容。
2. **依据当前用户问题与证据需求选择关系扩展方向。** 例如：
   - “X 是什么？”：优先当前 Claim，无需默认大范围展开；
   - “为什么决定 X？”：优先相关 Record、Source；
   - “X 如何演变？”：优先 History、前后继 Record；
   - “X 影响什么？”：优先相关 `derived` 依赖与可能受影响的 Backlinks；
   - “X 与 Y 有什么关系？”：考虑 Wikilinks、Backlinks 及 GR-002 的潜在临时关联。
3. **不按固定跳数无条件展开整个图。** 特别是普通 Wikilinks/Backlinks 的存在，不意味着必须读取每个邻居；显式 KF 来源仍按 F-008 规则履行检查，不能以预算或摘要跳过必要的来源核查。
4. **保留 Agent 的进一步探索能力。** 常见问题可只读取最相关的证据；复杂问题可以依据未解决的证据缺口继续展开，不因一次搜索已经返回足够数量的文件而阻止后续探索。

## 尚未确定（OPEN / PROPOSED）

- Token 预算与上下文装配、具体默认预算、片段选择策略；
- Agent 与 CLI 对每一次扩展决定的细分职责和协议；
- Obsidian/Headless Adapter 的实现，以及评测阈值。

## 依据与约束

- PR #95 的 `evals/experiments/obsidian-headless/scripts/plan.ts` 仅在关键词结果不足 K 时追加链接邻居，不构成对按问题意图主动扩展图的验证。
- KF v1.0 的关系语义、版本与来源检查仍是权威规范。
- 本决定不新增 KF 字段、不自动把探索关系升级为证据，也不授权实现 CLI-002。
