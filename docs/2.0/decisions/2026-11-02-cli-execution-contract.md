# CLI-001 — Knowlery CLI 的可选性、规范权威与安全边界

**日期：** 2026-11-02  
**状态：** ACCEPTED（Owner 在讨论中提出四项修订，并明确表示在补充后接受）  
**适用范围：** Knowlery 2.0 / Knowledge Format v1.0 / CLI Level 1 设计  
**相关决策：** A-002、A-003、A-004、I-001、I-002、F-005、F-007、F-008

## 已接受的决定

> **Knowlery CLI 是针对 Knowledge Format（KF）的确定性知识操作实现，不是知识规则的第二份权威规范。** 对拥有直接文件工具的 Agent，它是可选的可靠性增强层；对只能通过 Knowlery MCP 访问 Vault 的 Agent，CLI 支撑的 MCP 路径是该环境访问知识库的唯一通路。CLI 可以强制执行经由自身受控接口的、可确定性检查的 KF 约束，但不能阻止绕过 CLI 的文件修改。CLI 或 stdio MCP 进程可以在会话期间存在，却不拥有权威知识状态；权威仍由持久的 Knowledge Format 资产承载。

### 1. 「可选」必须带环境前提

- **有直接文件工具（如 Bash、Shell、文件读写）的 Agent**：即使未安装 CLI，也必须能按照 KF v1.0 与 `CONVENTIONS.md` 读取、编写和维护知识。CLI 是增强层，不是 Format 理解的前置条件。
- **只能使用 Knowlery MCP 访问 Vault 的 Agent**：不能回退到本地文件工具；CLI 支撑的 MCP 接入路径是该环境的唯一 Knowlery 访问通路。第一阶段 Claude Desktop 桌面扩展是这类环境的目标案例；未来远程 MCP Connector 可以属于此类。
- 「唯一通路」限定为**该 Agent 被赋予的 Vault 访问手段**，不是宣称文件系统只能被 CLI 访问，也不预先决定 MCP Server 是通过 CLI 子进程还是共享操作实现调用。部署和进程边界后续设计。

### 2. CLI 实现 KF，不创造第二份知识规范

- **KF v1.0 是知识格式、语义和治理规则的权威来源**。CLI 只实现、验证、机械化执行其中已定义的规则；不能增加未写入 KF 的知识语义要求，并使其成为事实上的第二套知识规范。
- 与 KF 冲突时，**KF 优先**，需要修正 CLI，不能以 CLI 当前行为反向解释 KF。
- 如果需要新的**知识层规范**（例如新状态、必填字段、Claim 迁移规则或证据语义），应先提出并接受 KF 修订，再更改 CLI 实现。遵循现有 Format 决策升级/实验流程，不静默改变已接受的 v1.0。
- CLI 所必需的**实现级安全措施**（例如拒绝路径穿越、权限检查、原子文件替换流程）可以由操作层设计与测试，但不能偷偷改变符合 KF 的文件在无 CLI 模式下的合法性。这类措施应与知识格式语义区分、明确文档化。

### 3. 确定性强制保障仅对受控写入成立

- 对**经过 CLI 写入接口**的操作，可检查并在违反约束时拒绝：受保护 Claim、版本前置条件、引用/结构合法性、历史保留，以及 F-005/F-007 所需的其他明确契约。具体实现和符合性测试仍是 Level 1 工作，当前不宣称已实现。
- 对**绕过 CLI 的写入**（例如人类在 Obsidian 中直接编辑，或另一个 Agent 用 Shell 修改），CLI 不能阻止行为；可以在后续操作中通过预期版本与当前内容的比较、来源校验、`validate` 等手段检测**可观测的变化或格式违规**。
- 事后检测**有条件**：写前 hash 比对需要可信的基线/期望版本；没有记录的合法格式内容改动未必可被判定为异常。`validate` 不保证判断语义正确、授权真实性或发现所有外部编辑。
- 如果外部文件在 CLI 完成检查与提交之间再次变化，Level 1 必须验证并发边界，不能仅以一次较早的 hash 比对宣称不会丢失写入；真正的互斥/原子性保证需在目标平台实测。
- **F-005 与 F-007 仍为 PARTIAL**，直到上述边界通过测试，且治理权威状态在跨客户端情境下可持久保留。

### 4. No Core Runtime 不等于「不存在长寿命进程」

- CLI 命令可以短时运行；stdio MCP Server 可以在会话期间保持进程运行。**进程寿命不是架构原则的判断标准**。
- **每次知识操作都应从持久文件读取并核验其所依赖的权威状态**，不得仅依赖进程内会话状态、陈旧缓存或运行索引作为事实来源。无需为了每次操作强制扫描整个 Vault；可以按需加载相关文件，并校验所需版本/依赖。
- `.knowlery/` 下的**派生缓存和索引必须能删除并重建**，不承担独立的知识事实或不可恢复的治理权威。不能将该承诺扩大为「整个 `.knowlery/` 目录都可删除」：配置及其他非派生状态必须按 KF 资产/配置边界分别处理。
- 这个原则不排除会话期 MCP 进程、加速缓存或只读索引；只要求它们不成为独立权威知识库。与 A-003 No full Core Runtime 相容。

## 理由与证据

- KF v1.0 与 `format/CONVENTIONS.md` 已规定：Agent 只用文件工具仍能理解知识结构和更新规则；`protected`、历史、版本和读取验证具有明确语义。
- Level 0 已验证文件工具工作流在限定测试中可用；**没有**验证跨进程原子写入、并发保护或受保护主张的代码级强制。
- 当前 `docs/2.0/DECISIONS.md` 将 F-005（治理持久化）与 F-007（写入安全）标为 PARTIAL，因此本决策只接受原则和验收边界，不批准某一实现。
- Owner 对原「CLI 为可选确定性增强层」提案提出上述四项修改，并明确在修改后接受。

## 与旧文档的术语协调

KF v1.0 已接受文本中的 **`Connector`** 曾泛指确定性知识操作实现。依据 I-001，面向新架构时 **MCP Connector** 特指协议接入。故 KF 所称「Connector 强制 `protected`、安全写入」的**操作责任归属于 CLI/共享的确定性操作能力**；MCP Connector 只是其中一种调用入口。此处是术语解释，不变更任何 KF 规则。

## 对比与取舍

| 候选 | 结论 |
| --- | --- |
| 所有 Agent 均必须通过 CLI，禁止直接文件工具 | 不采用；与 Format-first/Level 0 的可移植性冲突 |
| CLI 一律可选，MCP-only Agent 也能直接修改文件 | 不采用；该类 Agent 没有 Vault 文件工具 |
| CLI 可自行定义新治理/格式语义 | 不采用；会产生第二套不可移植规范 |
| 安装了 CLI 就能阻止所有外部写入 | 不采用；超出 CLI 写入路径的保护范围 |
| 会话期 stdio MCP 进程等于新 Core Runtime | 不采用；判断依据是事实来源和状态所有权 |

## Level 1 符合性与验收边界（待设计，不代表通过）

1. 在**无 CLI、有文件工具**的 Agent 环境，以 KF + `CONVENTIONS.md` 完成读取、创建、局部更新、冲突标记，并正确告知弱保证。
2. 在**仅提供 MCP 工具**的环境完成授权读取/写入；无法连接 CLI 支撑的 MCP 时不能伪造文件工具回退。
3. CLI 对自身写入拒绝违反 KF 的结构、保护、版本前置条件；并以测试证明合法写入保留记录和引用。
4. 人类或外部 Agent 绕过 CLI 改写：可检测的版本漂移/格式违规能在后续验证时报告；无基线时明确 `unknown` / 无法证明，而非声称完全检测。
5. 同时写入、检查与提交之间竞态、失败恢复、治理状态跨客户端一致性均有独立测试。
6. 运行 CLI / MCP、重启 MCP、删除**派生缓存**后，知识语义和必须持久化的治理状态保持不变；若缺少配置则应单独报告，不把配置误当缓存。
