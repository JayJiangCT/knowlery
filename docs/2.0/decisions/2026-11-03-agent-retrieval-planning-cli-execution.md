# GR-009 — Agent 规划检索，Knowlery CLI 执行确定性知识操作

**日期：** 2026-11-03  
**状态：** ACCEPTED（Owner 明确接受 Agent / Skills 识别问题意图与规划探索，Knowlery CLI 负责确定性检索、关系解析、证据读取与校验）  
**范围：** Knowlery 2.0 / Graph-guided Retrieval 分工原则；不等于 CLI-002 命令及实现获批  
**相关决定：** A-002、A-004、CLI-001、SK-001、GR-001 ～ GR-008、F-006、F-008

## 已接受的决定

1. **Agent / Skills 负责智能判断。** 包括理解用户问题与检索目标、选择/重写查询、判断优先探索哪些关系及证据、决定是否继续探索、识别回答所需证据是否足够，并在证据缺失或矛盾时说明不确定性。Agent 的语义判断不是确定性的正确性保证。
2. **Knowlery CLI 负责确定性知识操作。** 在明确输入与访问权限范围内执行检索、解析 Wikilinks / Backlinks 与 KF 关系、读取与定位 Claim / Record / Source、核对可以机械校验的版本和来源状态、输出可追踪的证据索引及按需证据内容。遵守 GR-005/006 单次调用资源边界、GR-007 无状态续读和 GR-008 分层 Evidence Pack 原则。
3. **不要求 CLI 内置 LLM 或负责开放式语义推理。** CLI 不得仅凭启发式分类声称掌握问题意图、某段证据的语义蕴含或最终答案的真实性。CLI 可以执行由 Agent 指定的多查询、去重、排序、链接扩展等**明确且可复现的确定性批处理**，以降低多次工具往返，但批处理不能暗中替代 Agent 的开放式决策。
4. **CLI 并非所有 Agent 的强制路径。** 遵循 CLI-001：有文件工具的 Agent 可以按 KF v1.0 直接读取/处理；只能使用 Knowlery MCP 的 Agent 通过 CLI 所支撑的 MCP 能力访问。Obsidian CLI 可作为 Knowlery CLI 内部可选 Adapter，不是 Agent 必须直连的命令。
5. **检索与证据权威分离。** Knowledge Format v1.0 是证据、Claim 状态和来源校验的权威定义；CLI 负责机械化执行，不得另建一套知识语义。GR-002 的无链接语义关联发现仍由 Agent 进行判断并作为临时候选，不在检索中直接写回；F-008 来源检查义务不会因 Agent 觉得“已理解”而豁免。

## 示例职责划分（非最终 CLI 语法）

问题：“为什么修改 Weight Eligibility 规则？”

- Agent 认定这是“决策原因”类问题，提出检索目标与优先路线（当前 Claim → 决策 Record → Source）。
- CLI 检索并返回当前知识入口、已有 KF 来源/演进关系、关联定位和可确定的检查状态；根据明确选择按需读取相关 Record / Source。
- Agent 根据证据缺口决定下一步和回答范围。CLI 不能替 Agent 声称“回答已证明正确”。

## 技术可行性与验证边界

- 已确认的 Obsidian CLI 原语与 PR #95 的检索实验为搜索、链接解析和多路确定性执行提供**局部工程证据**，但并未完整证明 GR-009 的多轮 Agent 规划—工具执行闭环可靠可用。
- 多轮工具调用是已有 Agent Harness 的常见能力；对特定 Harness 的接入、MCP-only、超时与资源截断行为必须在后续技术原型中验证。
- CLI 不持有 LLM 全局上下文，不能硬性保证跨调用总 Token 或答案语义正确性；GR-004/005 继续生效。
- 如果后续实验表明 Agent 规划成本或不稳定性过高，可单独提出可复现的确定性便捷操作或 Skill 工作流改进，但不得悄然把 CLI 变成隐藏的自主 Agent。
