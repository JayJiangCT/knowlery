# GR-006 — 单次输出预算与完整证据单元

**日期：** 2026-11-03  
**状态：** ACCEPTED（Owner 明确认可组合式单次硬约束、Token 估算及不伪装截断证据的处理原则）  
**范围：** Knowlery 2.0 / Graph-guided Retrieval 的输出与资源限制原则  
**相关决定：** GR-003、GR-004、GR-005、CLI-001、F-003、F-004、F-008

## 已接受的决定

1. **组合式单次硬约束。** CLI 对自己能控制的单次操作设置确定性结果数量、实际输出字节数和执行时间限制。Token 用量只作为明确标注的估算，不能在未选定目标 tokenizer 与完整 Harness 上下文时宣称精确。
2. **完整证据单元优先。** 需要返回 Claim、Record、Source 证据片段时，尽量输出具有完整语义边界和明确定位的单元（例如一个 Claim、一个可验证的来源片段），不因为剩余字节不足就随意截断正文并将其冒充完整证据。
3. **预算不足时退回定位信息。** 如果下一个完整证据单元放不进当前输出预算，返回该单元的标识、来源或定位、未返回/部分返回的显式状态及供下一次调用继续读取的信息；不得默默丢弃，也不得宣称该单元已完成来源验证。可分块读取大型 Source，但每块必须明确其范围及部分性。
4. **截断与证据充分必须分离。** 请求执行失败、超时、候选列表截断、内容未完整读取、来源未核查，应分别以机器可识别的状态显式报告，不能将仅部分读到的内容当成完整证据，也不能用“预算耗尽”替代 KF v1.0 F-008 的 Source 核查。
5. **有界失败。** 约束包括协议/元数据本身的输出开销；极小预算下不能强行返回超标 JSON，应以事先定义的最小错误响应或非零退出状态说明无法满足约束。具体最小响应、字节边界及退出码尚待设计与测试。

## 技术边界

- CLI 能独立测量经自己输出的字节数量、结果条数，并对本地受控操作执行超时。外部 Obsidian CLI 偶发挂起、子进程退出和取消需要有界失败与回归测试；本决定不是对所有环境下绝对实时终止的保证。
- Tokenizer 依模型/平台而异，CLI 无法独立测算 Agent 全部上下文。字节预算不保证与 Token 预算之间存在固定比例。
- “完整证据单元”是输出格式上的完整，不代表已证明其真实性。记录来源身份、Claim anchor、引用片段、版本和 KF 校验状态时仍必须按照现有 KF 语义，不擅自增加新证据规则。
- 对超大 Source，定位/范围分块在技术上可行，但跨调用版本变化可能使续读不一致。具体的版本前置条件、稳定标识、分页协议与失效处理需要另行设计。

## 尚待决定（OPEN / PROPOSED）

- 默认单次结果条数、最大输出字节和超时的具体数值与上限。
- JSON 结构、Claim/Source 片段的单元边界、部分内容标识、续读方式和版本校验协议。
- Token 估算算法及可验证偏差。
- 如何把来自不同 Backend 的检索结果组织为证据包，以及相关评测阈值。

**边界：** 本决定确认 CLI-002 的资源和证据输出原则，不代表相关命令、分页或预算控制已经实现、测试通过，也不构成 CLI-002 整体批准。
