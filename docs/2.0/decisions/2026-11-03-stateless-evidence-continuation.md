# GR-007 — 无状态证据续读与版本检查

**日期：** 2026-11-03  
**状态：** ACCEPTED（Owner 明确认可第一版采用「无状态续读 + 版本检查」）  
**范围：** Knowlery 2.0 / Graph-guided Retrieval 第一版证据续读契约原则  
**相关决定：** GR-003、GR-004、GR-005、GR-006、CLI-001、F-003、F-004、F-008

## 已接受的决定

1. **第一版优先采用无状态续读。** CLI 对无法在本次输出预算内返回的证据，向 Agent 提供可再次请求的明确定位（如 Vault 内文件路径、KF Claim anchor、来源标识、必要的阅读范围）及版本前置条件；后续调用重新定位、重新读取，不依赖此前 CLI 进程内存或服务端持久检索会话。
2. **续读前验证相关内容版本。** 在本次读取前比较当前相关证据范围与续读请求的预期版本。符合时继续读取；发生变更时明确报告 stale / version mismatch，并让 Agent 重新定位或核对，不静默拼接不同版本的证据。
3. **保留不完整状态。** 由于预算、文件变更、删除、重命名、anchor 失效或权限等原因无法继续时，提供机器可识别的未完成/失效状态。不能把部分 Source / Claim 内容当成完整证据或宣称已经满足 KF v1.0 F-008 的验证要求。
4. **不新增权威知识状态。** 无状态续读不得依赖独立的、不可恢复的知识数据库，符合 CLI-001 的文件权威和无完整 Core Runtime 原则；可以利用 KF v1.0 已定义的路径、Claim anchors 和按证据范围计算的版本，同时尊重不同页面角色的 digest 范围。
5. **不承诺整个 Vault 的快照一致性。** 单份证据的版本前置条件不能保证跨多文件、跨多次检索时，链接图、排序、候选集及所有 Source 都处于同一时间快照。对跨文件的一致性需求须单独设计，不将其偷换成此决定已有保障。

## 技术边界与风险

- 路径、anchor、版本检查与再次读取属于本地文件及 Obsidian CLI 现有原语可实现的确定性操作，具体 CLI 形状和可靠性仍需实现及验收。
- 对 Claim 的局部指纹、Source 文件证据 digest、Record 证据范围，须严格复用 KF v1.0 的版本语义。任何请求中客户端给出的版本只代表预期值，不是已核验事实。
- **检查与读取之间的竞态**需要在实现时测试。仅在读取前计算一次版本不足以保证读取时没有发生改变；可对实际返回内容再计算核验，失败时拒绝或报告变更，但对跨文件事务一致性仍不作保证。
- 超长来源可以分范围读取，但必须清楚表示分块边界、每块的关联版本及整份来源是否已被检验。
- 稳定搜索结果分页不同于按定位续读单份证据。若 Vault 在两次搜索间发生变化，按 rank/offset 重新运行可能漏项或重复；**本决定不批准稳定的跨调用全量结果集分页**，其失效策略仍待明确。

## 尚待设计 / 测试（OPEN / PROPOSED）

- 文件定位、Claim anchor、读取范围、预期版本和无效定位的 JSON/CLI 参数形状。
- 超大 Source 分块读取及可重试失败的具体协议。
- 并发编辑、文件移动、内容版本失效、分块合并、超时/取消与存储失效的测试。
- 结果集分页和排序稳定性是否需要 snapshot token 或额外可重建索引；不可借此悄然引入权威会话数据库。
- Evidence Pack 的组织、裁剪、证据状态展示以及评测方案。

**范围说明：** 本决策为设计原则，非 CLI-002 全部契约的批准，也不宣称无状态续读已完成产品实现。
