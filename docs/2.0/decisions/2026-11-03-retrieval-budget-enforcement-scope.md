# GR-005 — 检索资源预算：单次调用硬约束，任务级软约束

**日期：** 2026-11-03  
**状态：** ACCEPTED（Owner 明确接受任务级预算采用软约束）  
**范围：** Knowlery 2.0 / Graph-guided Retrieval 第一版资源约束原则  
**相关决定：** GR-003、GR-004、CLI-001、A-003、A-004、F-008

## 已接受的决定

1. **单次 CLI 操作的资源限制是硬约束。** 在 CLI 实际控制的调用范围内，以确定性规则限制可控制的数量，例如结果条数、读取范围与输出字节，以及执行超时；实现时必须报告截断、超时和失败状态。精确参数、命令与具体实现尚待设计和测试。
2. **跨多次调用的任务级预算在第一版采用 Agent / Skills 协作管理的软约束。** Agent 根据用户问题、已经消耗的检索输出及剩余证据缺口，主动决定是否继续调用 CLI。任务级软约束不是可强制执行的资源上限，Agent 忘记约定、重开会话、换用其他工具或绕过 CLI 时可能超限。
3. **不为第一版任务级预算强制引入会话账本、共享状态协调器或独立 Core Runtime。** 如果后续评测显示软约束带来明显问题，可重新提议可追踪会话的硬预算；本决策并不禁止未来实现。
4. **CLI 仅能约束自己返回的内容，不能直接知道或准确约束 Agent 的完整 LLM 上下文。** 在尚未选定统一 tokenizer 之前，不将“Token 数量”视作 CLI 能保证的精确硬指标；可使用可验证的字节数/结果数/读取范围/时间限额，以及明确标注为估算的 Token 消耗。
5. **达到预算与获得充分证据是两回事。** 预算耗尽或单次截断时，返回未完成状态，不声称证据已充分；若涉及 KF v1.0 F-008 必须检查的来源，尚未完成核查时不能将相应 Claim 宣称已验证。

## 技术可行性与已知风险

- CLI 的逐调用结果数、字节输出和执行时限可通过局部计数、确定性截断及超时机制实现；PR #95 对检索调用数与 Obsidian CLI 超时/重试已有实验经验，但尚未实现或验证这里定义的完整资源契约。
- Agent/Skills 可以依据任务上下文协调多轮工具调用，但属于模型行为约定，不保证绝对遵循；跨独立 CLI 进程无法仅靠本次调用天然获知累计用量。
- 后续实验应观察任务累计资源开销、Agent 是否遵守软预算、重要来源校验的完成率与误判停止的比例。任何任务级预算的强制保证须作为独立设计和验收项目。
